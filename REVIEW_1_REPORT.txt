PROJECT TITLE:
Shared-Account Elimination Workflow Using Accountable Delegation and Session Attribution for a Hospital

1. PROJECT OVERVIEW
Hospital clinical workstations (Radiology, Lab, Pharmacy, Wards, Billing, IT) routinely use shared logins (radiology_shared, lab_shared, pharmacy_shared, ward_shared, billing_shared, admin_shared) across permanent, visiting, intern, and contractor staff for shift handoffs. When sensitive actions occur (ePHI access, lab edits, prescription changes, record exports), audit logs record only generic shared accounts, destroying non-repudiation and accountability.

This project delivers a working proof of concept for an Accountable Delegation and Session Attribution Pipeline. By correlating shift delegations, session bindings, device fingerprints, and subnets, the system attributes sensitive actions to individual human identities with calibrated confidence and transparent audit explanations.

For Review 1 (35% milestone), the project establishes core data models, shared account inventory, shift delegations, synthetic multi-department data, event ingestion with SHA-256 deduplication, baseline attribution, prototype multi-signal attribution, comparative metrics, FastAPI backend, SOC web dashboard, and automated tests.

2. COMPLETED SO FAR
- User Roster: 18 synthetic staff across 4 workforce categories in 7 departments.
- Workforce Categories: Modeled permanent, visiting, intern, and contractor staff.
- Shared Accounts: 6 clinical accounts across 6 hospital subsystems with risk levels.
- Delegation Registry: 26 shift delegations mapping staff to shared accounts.
- Synthetic Hospital Data: 364 system events across 4 days with 205 sensitive clinical actions.
- Event Ingestion: Validates fields and blocks duplicates via SHA-256 payload hashing.
- Privileged Actions: Catalog of 10 sensitive clinical and admin operation types.
- Database Models: SQLite schema via SQLAlchemy ORM across 6 core tables.
- Baseline Attribution: Shift-count rule (1 user=attributed, >1=ambiguous, 0=unattributed).
- Session Attribution: Multi-signal scoring across delegation, session, device, subnet, dept.
- Evidence Scoring: Delegation (40), session (30), device (15), subnet (10), dept (5).
- Confidence Scoring: High (80-100), Medium (60-79), Low (40-59), Unattributed/Ambiguous.
- Attribution Explanation: Per-event audit trail detailing matched signals and failure causes.
- Attribution Metric: Formula quantifying percentage of sensitive actions attributed.
- Backend APIs: FastAPI REST service with 10 operational endpoints.
- Frontend Dashboard: SOC web UI with 5 tabs (Overview, Accounts, Events, Comparison, Roster).
- Event Explorer & Modal: Searchable log table with filters and evidence inspection modal.
- Automated Tests: 11 passing unit tests covering logic, edge cases, formulas (100% pass).

3. KEY FEATURES / MODULES COMPLETED
- User Management (app/models/user.py): Staff records with role, dept, status, category.
- Shared Accounts (app/models/shared_account.py): Tracks workstations, host systems, risk levels.
- Delegation Registry (app/models/authorization.py): Tracks shift authorization windows and approvers.
- Log Processing (app/services/event_processor.py): Ingests events, computes SHA-256 hash, blocks duplicates.
- Privileged Action Detection (app/models/privileged_action.py): Catalogs 10 high-risk clinical operations.
- Baseline Engine (app/services/baseline.py): Shift count: 1 delegate=Attributed (60%), >1=Ambiguous (30%), 0=Unattributed (0%).
- Prototype Engine (app/services/attribution.py): 5-signal weighted scoring; ties within 10 pts flag Ambiguous.
- Metrics Service (app/services/metrics.py): Computes attribution rates, net lift, confidence tiers, failure reasons.

Implemented Pipeline:
Data Sources -> Ingestion/Deduplication -> Shared Account Detection -> Candidate Scoring -> Attribution Engines -> Metrics Service -> SOC Dashboard/API.
